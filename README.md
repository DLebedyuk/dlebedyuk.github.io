# Портфолио

Next.js 14 (App Router) + TypeScript + Tailwind + Framer Motion, статический экспорт под GitHub Pages
(репозиторий `dlebedyuk.github.io`). Сборка проверена локально (`npm run build` проходит, статический
экспорт генерирует 4 страницы).

## Статус

С кейсами теперь настоящий материал — из `port-transit-career-cases.md`. Раздел Engineering Case
Studies больше не пустые заглушки: 15 карточек, у каждой есть реальный контекст, роль и решения.
Но ни у одной нет подтверждённых цифр (в исходнике так и написано — метрики не выдумывались), поэтому
бейдж «Черновик» на карточке остался у всех, а под капотом у каждой есть `draftNote` — короткая
пометка, чего именно не хватает, она раскрывается вместе с кейсом.

Полностью пустых тем осталось две: **ФГИС «Зерно»** и **SOAP-интеграции** — этого в присланном
материале не было вообще.

## Структура контента

Весь текст сайта лежит в `content/*.ts`, не в компонентах:

- `content/profile.ts` — позиционирование, summary и `Things I Enjoy Solving`. Обновлено на основе
  реального "Короткого позиционирования" и "Что повторяется в опыте" из материала.
- `content/case-studies.ts` — 15 кейсов. Часть из твоего исходного ТЗ (инцидент на терминале, два
  отдельных кейса по ЭТрН, Астрал, ГЛОНАСС, SOAP, две отдельные автоматизации, релизы, управление
  командами), плюс новые, которых не было в изначальном списке: продуктовое направление для
  перевозчиков, интеграция с Контуром, production-расследование, Telegram-бот для накладных.
- `content/skills.ts` — теперь из "Навыки, подтверждаемые кейсами" + конкретные системы/технологии
  из кейсов. Backend/DevOps как личный стек разработки — всё ещё TODO.
- `content/architecture.ts` — добавлен узел «Контур» (реальная API-интеграция).
- `content/timeline.ts`, `content/achievements.ts` — без изменений в сути: даты/должности/цифр в
  материале не было.

## Что я сама решила при разборе материала

- Кейс «Инцидент с остановкой терминала» — использовала историю про сбой с удалением таймслотов
  (единственный инцидент в материале, похожий по описанию).
- «Работа с ЭТРН» разделила на два кейса: запуск приёма по ЭТрН на терминале «Подскок» (дедлайн
  1 сентября) и отдельно — сценарии ЭТрН/роуминг ЭДО. Это две разные истории с разной фактурой.
- «Автоматизация процессов» тоже разделила на два: сертификаты и платежи — тоже разные истории.
- «Работа с релизами» и «Управление командами» опираются на один и тот же абзац источника (про
  несколько параллельных проектов) — сейчас они тонкие и почти дублируют друг друга. Возможно, стоит
  снова объединить в один кейс, когда появятся детали — решай сама.
- В кейсе production-расследования оставила твою же оговорку: сам файл с деталями (готовили с
  Claude в исходном чате) в этой выгрузке не было, и похоже, что это связано с отдельно упомянутым
  «расследованием delete_who» — стоит подтвердить.
- Тему «аномальные смены на терминале» из твоего материала не стала оформлять отдельным кейсом —
  там даже нет понятного результата (была ли причина найдена). Если захочешь — допишу.

## Как запустить локально

```bash
npm install
npm run dev       # http://localhost:3000
```

## Как задеплоить

`.github/workflows/deploy.yml` уже настроен: пуш в `main` → сборка → публикация в GitHub Pages.
В репозитории один раз проверь: **Settings → Pages → Build and deployment → Source → "GitHub
Actions"** (если там всё ещё "Deploy from a branch" — сайт будет отдавать голый README вместо сборки,
так уже было один раз).

```bash
git add .
git commit -m "add real case studies from port-transit-career-cases.md"
git push
```
